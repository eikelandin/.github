# Security policy

This policy applies to every public repository of [@eikelandin](https://github.com/eikelandin) without a `SECURITY.md` of its own.

## Supported versions

Fixes go into the latest release of each project. A repository without releases gets fixes on its default branch (`main`) only.

## Reporting a vulnerability

Report it privately, not as a public issue, pull request or discussion: open the affected repository's Security tab and choose "Report a vulnerability" ([GitHub private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)). Include the affected version, the component and the steps to reproduce.

## What happens next

- Acknowledgment of the report within 14 days.
- An assessment (accepted or declined, with the reason) within 30 days.
- For an accepted report, a fix or a mitigation within 90 days of the report; the advisory names the date if it takes longer.

The discussion happens in the draft advisory. A fixed vulnerability is published as a GitHub security advisory together with the fix, crediting the reporter unless they ask not to be named.
